# Remote SSH Connect

## 개요

이 문서는 Mac에서 Raspberry Pi(`pi@192.168.45.4`)에 접속할 때 사용한
`codex-pi.sock`의 용도와 동작 원리를 설명한다.

`codex-pi.sock`은 Raspberry Pi에 직접 연결되는 네트워크 소켓이 아니다. Mac에서
이미 인증을 마친 SSH 연결(마스터 연결)을 다른 SSH 명령이 재사용할 수 있도록 만든
로컬 Unix 도메인 소켓이다. OpenSSH에서는 이 기능을 연결 다중화(connection
multiplexing) 또는 ControlMaster라고 부른다.

## 왜 공유 소켓이 필요했는가

사용자가 직접 연 터미널과 Codex가 명령을 실행하는 셸은 서로 다른 프로세스와 세션이다.
따라서 사용자의 터미널에서 비밀번호로 SSH 로그인을 완료했더라도, 그 인증 결과가
Codex의 셸에 자동으로 전달되지는 않는다.

초기 접속이 실패한 이유는 다음과 같다.

- Codex 셸의 SSH 에이전트에 사용할 개인 키가 없었다.
- 기존 사용자 터미널의 비밀번호 인증 상태는 다른 SSH 프로세스에서 재사용할 수 없었다.
- 이미 열려 있던 일반 SSH 세션에는 다른 프로세스가 접속할 제어 소켓이 없었다.

이를 해결하기 위해 사용자가 인증하는 SSH 프로세스를 **마스터 연결**로 열고, 해당
연결을 가리키는 `codex-pi.sock`을 생성했다. 이후 Codex의 SSH 명령은 새로 인증하지
않고 이 마스터 연결 안에 논리적인 SSH 채널을 추가한다.

## 구성 요소

| 구성 요소 | 역할 |
| --- | --- |
| SSH 서버 | Raspberry Pi의 `sshd`; 실제 원격 명령을 처리한다. |
| 마스터 SSH 프로세스 | 사용자가 인증하여 생성한 Mac의 SSH 연결을 유지한다. |
| `codex-pi.sock` | 다른 로컬 SSH 클라이언트가 마스터 프로세스에 요청을 전달하는 Unix 도메인 소켓이다. |
| 추가 SSH 클라이언트 | 소켓을 통해 기존 연결에 새 세션이나 명령 채널을 요청한다. |

## 연결 흐름

```text
Mac
│
├─ 사용자 터미널
│   └─ ssh 마스터 프로세스 ───── 암호화된 TCP 연결 ───── Raspberry Pi sshd
│          │                                             192.168.45.4:22
│          │
│          └─ codex-pi.sock (로컬 Unix 도메인 소켓)
│                    ▲
│                    │ 제어 요청 및 새 SSH 채널 요청
│                    │
└─ Codex가 실행한 ssh -S 명령
```

처리 순서는 다음과 같다.

1. 사용자가 Mac에서 마스터 SSH 명령을 실행한다.
2. SSH 클라이언트가 Raspberry Pi와 호스트 키 확인, 사용자 인증, 암호화 협상을 수행한다.
3. 인증에 성공한 SSH 프로세스는 원격 TCP 연결을 유지하면서 로컬에
   `codex-pi.sock`을 연다.
4. Codex가 `ssh -S ...`를 실행하면 해당 소켓을 통해 마스터 프로세스에 새 세션을
   요청한다.
5. 마스터 프로세스는 기존 암호화 연결 내부에 새 논리 채널을 만들고 원격 명령을
   전달한다.
6. 새 TCP 연결과 사용자 인증을 반복하지 않으므로 Codex도 Raspberry Pi에 접근할 수
   있다.

## 사용한 명령

### 1. 마스터 연결 생성

이 명령은 **Raspberry Pi 내부가 아니라 Mac의 로컬 터미널**에서 실행해야 한다.

```bash
ssh -M \
  -S /Users/donghun2/workspace/rasberry_pi/codex-pi.sock \
  pi@192.168.45.4
```

옵션의 의미는 다음과 같다.

- `-M`: 현재 SSH 프로세스를 연결 공유용 마스터로 동작시킨다.
- `-S <경로>`: 마스터 제어 소켓의 경로를 지정한다.
- `pi@192.168.45.4`: 원격 사용자와 Raspberry Pi 주소이다.

사용자가 이 명령에서 비밀번호 또는 다른 인증 수단으로 로그인한다. 마스터 터미널과
연결이 유지되는 동안 소켓도 사용할 수 있다.

### 2. 공유 연결 사용

```bash
ssh \
  -S /Users/donghun2/workspace/rasberry_pi/codex-pi.sock \
  pi@192.168.45.4 \
  'hostname; id; uptime'
```

이 명령은 `codex-pi.sock`을 통해 기존 마스터 연결을 찾는다. 접속 대상과 사용자가
마스터 연결의 대상과 일치하면 새 인증 없이 원격 명령이 실행된다.

### 3. 마스터 상태 확인

```bash
ssh \
  -S /Users/donghun2/workspace/rasberry_pi/codex-pi.sock \
  -O check \
  pi@192.168.45.4
```

`-O check`는 마스터 프로세스가 살아 있는지 확인하는 제어 명령이다.

### 4. 마스터 연결 종료

마스터로 접속한 터미널에서 `exit`를 실행하거나 다음 명령으로 마스터 연결을 종료할 수
있다.

```bash
ssh \
  -S /Users/donghun2/workspace/rasberry_pi/codex-pi.sock \
  -O exit \
  pi@192.168.45.4
```

정상 종료되면 제어 소켓도 제거된다. 마스터 프로세스가 비정상 종료되어 소켓 파일만
남았다면 그 파일은 더 이상 접속에 사용할 수 없는 오래된(stale) 소켓이다.

## 접속이 가능해진 핵심 이유

SSH 비밀번호나 개인 키가 Codex에 전달된 것은 아니다. 사용자가 인증하여 만든 마스터
SSH 프로세스가 인증된 연결의 소유자이며, Codex는 같은 Mac 사용자 권한으로 로컬 제어
소켓에 접근해 그 연결에 새 채널을 요청한 것이다.

즉, 공유된 것은 **인증 정보 자체가 아니라 이미 인증된 SSH 연결을 사용할 수 있는
통로**이다. 마스터 연결이 종료되면 이 통로도 사라지며, 다음 접속에는 다시 인증해야
한다.

## 보안상 주의할 점

- 제어 소켓에 접근할 수 있는 로컬 사용자는 마스터 연결의 권한으로 원격 명령을 실행할
  수 있다. 소켓 파일 권한은 소유자만 접근하도록 유지해야 한다.
- 현재 소켓은 `srw-------` 형태로 생성되어 소유자만 읽고 쓸 수 있다.
- 소켓을 공유 디렉터리, 네트워크 파일 시스템 또는 다른 사용자가 접근 가능한 경로에
  만들지 않는다.
- 소켓은 비밀번호나 개인 키 파일은 아니지만, 살아 있는 동안에는 인증된 연결과 같은
  수준으로 보호해야 한다.
- 작업이 끝나면 `-O exit` 또는 마스터 터미널의 `exit`로 연결을 종료한다.
- `codex-pi.sock`은 실행 중에만 필요한 런타임 파일이므로 Git에 커밋하거나 백업할
  문서/소스 파일이 아니다.

## 일반 SSH 접속과의 차이

| 항목 | 일반 SSH 접속 | ControlMaster 공유 접속 |
| --- | --- | --- |
| TCP 연결 | 명령마다 새로 생성 | 기존 연결 재사용 |
| 사용자 인증 | 접속마다 수행 | 최초 마스터 접속에서 수행 |
| 연결 속도 | 협상과 인증 시간이 필요 | 새 채널만 열어 상대적으로 빠름 |
| 로컬 제어 소켓 | 사용하지 않음 | 필요함 |
| 마스터 종료 후 사용 | 각 연결이 독립적 | 새 공유 접속 불가 |

## 자동화 시 참고

반복 작업에서는 SSH 설정 파일(`~/.ssh/config`)에 `ControlMaster`, `ControlPath`,
`ControlPersist`를 설정해 연결 공유를 자동화할 수도 있다. 다만 이는 지속적인 접근
방식과 소켓 보관 정책을 변경하므로, 개인 키 기반 인증과 파일 권한을 함께 검토한 뒤
적용하는 것이 좋다.
